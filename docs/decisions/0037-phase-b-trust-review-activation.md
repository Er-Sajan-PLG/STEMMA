# DECISION 0037 — Phase B: trust & review activation (R2/R4/R6)

- **Date:** 2026-09-06
- **Status:** decided & implemented
- **Related:** ADR-0036 (webapp), ADR-0035 (ingest correctness), ADR-0031
  (rejected lifecycle), ADR-0033 (machine-readable validator),
  `docs/DEEP-DIVE-RECOMMENDATIONS.md` § Phase B.

## Context

The graph is validated but mostly unverified: 595/654 active connections carry no
evidence, only 3 canonical source records exist while 44 entity provenance.source
strings are unresolved, `related_to` is 371/654 connections (308 of them the
*only* edge for a pair), and **0/224 entities have been human-reviewed**. Phase B
is the "trust and review activation" pass: make those gaps visible, gate what the
gate should gate, and make entity human review a first-class, human-fired action.

## Decisions

### R2 — Evidence and source integrity
- **Validator ERROR:** `assertion.review.status == canonical` requires ≥1
  evidence item **or** an explicit axiomatic marker (type `axiom`, or type
  `other` whose description says `axiomatic`). No canonical claim is left
  unsupported by construction.
- **Validator WARNING (advisory):** every *active, non-rejected* assertion with
  empty evidence is surfaced (in the report; never blocks submission).
- **New derived report** `reports/academic-sources.json` + `.md`:
  unresolved entity provenance.source strings and unresolved evidence
  `source_ref`s. It drives human source backfill; it is not a gate.

### R4 — Relation vocabulary genericity
- **Derived report** `reports/relation-triage.json` + `.md`: groups
  `related_to`-only dependency candidates, measurement candidates, and
  already-specific redundant pairs.
- **Validator WARNING (advisory):** a `related_to`-only edge with a reserved
  relation whose domain/range fits is surfaced for human triage.
- **No bulk-relabel, ever.** These are review aids only.

### R6 — Review activation
- **`scripts/review_entity.py`** extends human review to canonical entities:
  `list`/`show`/`review`/`canonicalize`. It requires an active registered
  `human:` reviewer, writes `provenance.reviewer`/`reviewed_at` + entity
  `status`, and forbids `draft → canonical` (must go through `human_reviewed`).
- **`scripts/entity_review_campaign.py`** generates deterministic human
  worksheets (seed concepts per domain first, then by centrality) under
  `reports/entity-review-campaign/`. It never edits status.
- **`reports/curation-status.json`/`.md`** now include entity review coverage
  per domain/type/status.

## Consequences

- `scripts/validate.py` adds two advisory warning families + the canonical
  evidence ERROR. The tracked `reports/validation-report.json` therefore now
  carries a non-zero WARNING count; the Phase B test documents this and asserts
  the gate stays ERROR-free.
- `scripts/verify_all.py` and any subprocess callers now route through
  `sys.executable` so a virtualenv runner uses the venv's deps (PyYAML +
  jsonschema) consistently.
- `reports/dependency-review-campaign/`, `reports/entity-review-campaign/`,
  `reports/academic-sources.*`, `reports/relation-triage.*` are all git-tracked
  derived reports regenerated by the verify chain.
- No canonical schema/export version change, no canonical data edit, no new
  server/DB dependency.
